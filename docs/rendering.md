# 描画の設計と検証

## 純粋な決定とGPUの実行

`advance :: Input -> World -> (World, [Cue])` と1/60秒の時計、保存形式は変えていません。
画質やカメラを変えても世界の状態遷移へ設定値を渡しません。

1. `Render.Settings` がプリセットと個別指定から `RenderPlan` を導きます。
   各バッファの整数寸法、影の解像度、雲・接地陰影のサンプル数が明示されます。
   無効な効果のバッファは `Nothing` です。
2. `Mesh` はセルから形状を導き、反射色・発光・局所AO・素材を独立に保持します。
   太陽光を反射色へ焼き込みません。GPUへ渡す表現は正本ではありません。
3. `Render.Chunk` と `Render.Invalidation` が描画の分割・可視性・更新範囲を決めます。
   描画単位は8×8×8セル。編集や衝突の単位は1セルのままです。
   変更セルと26近傍だけがメッシュへ影響し、影の更新は別の描画パスが扱います。
4. `Render.Radiance` は描画コールバックを受けて計画を実行します。
   ゲームルール、セーブ、入力、世界の可変状態へアクセスしません。
   GPU資源の確保・解放はこの外側の処理です。

これは純粋な規則と描画方針を、状態を持つホストで実行する設計です。
GPUドライバまで純粋であるという主張や、ゲーム全体をFRPで記述したという主張ではありません。

## 描画経路

反射色を線形空間へ変換し、照明・発光・ブルーム・露出を計算したあと、一度だけ
ACES近似のトーンマッピングとsRGB変換を行います。RGBA16Fの実際の確保を確認し、
利用できない環境では線形RGBA8へ退避します。後者は明るい領域の保持に制約があります。

空・地形の照明・影・光の散乱は同じ光源方向を共有します。影は近距離と遠距離の
二つの深度画像から取り、境界で混ぜます。光源の画像平面で位置を丸め、移動時の
揺れを抑えます。画面外の物体も影を落とすので、影には専用の可視判定を使います。

雲は半解像度、接地陰影と光の散乱も半解像度、ブルームは各軸1/4の解像度で処理します。
ブルームは横・縦の分離フィルターです。接地陰影は実際の深度画像の寸法・視野角・
縦横比・near/farを使い、深度を使った補間で輪郭をまたぐにじみを抑えます。
写真の傾き・望遠・広角にも同じ投影を渡します。

## 負荷の選び方

| プリセット | 描画解像度 | 近距離／遠距離の影 | 雲のステップ数 | 接地陰影 | ブルーム |
| --- | --- | --- | --- | --- | --- |
| 高画質 | 100% | 4096 / 2048 | 24 | 16サンプル | オン |
| 標準 | 75% | 1024 / 1024 | 12 | 8サンプル | オン |
| 軽量 | 50% | なし | なし | なし | オフ |

解像度は縦横各軸の割合です。極端なウィンドウサイズでも各軸4096以下に収めます。
雲を切っても空そのものは残り、接地陰影を切っても形状由来の局所AOは残ります。
光の散乱は接地陰影のパス内で実行し、接地陰影または影を切ると省かれます。
写真のブルーム切り替えは、画質側の設定をさらに制限します。

WindowsではF4がプリセットを巡回します。起動時の個別指定は次のとおりです。
プリセットを先に適用し、個別指定で上書きします。F4は新しいプリセットへ戻します。

| 環境変数 | 値 |
| --- | --- |
| `GARDEN_QUALITY` | `high` / `balanced` / `light` |
| `GARDEN_SCALE` | `25` ～ `100` |
| `GARDEN_SHADOWS` | `off` / `soft` / `fine` |
| `GARDEN_CLOUDS` | `off` / `soft` / `fine` |
| `GARDEN_AO` | `off` / `soft` / `fine` |
| `GARDEN_BLOOM` | `off` / `on` |

ブラウザでは同じ指定を「描画の調整」から選べます。個別指定は画質を変えても維持され、
「画質に合わせる」で解除します。設定はローカルに保存され、ゲームのセーブには入りません。

## 不具合を防ぐ境界

- シェーダー失敗時にraylibの既定シェーダーへ黙って置き換わらないよう、IDも検査します。
- 半透明のAO結果を通常のアルファ合成で書くと結果が二重に掛かるため、専用パスでは
  クリアして置換します。終了時は通常のブレンド状態へ戻します。
- 自分が書いている深度画像を同時に読むことがないよう、影の描画前にサンプラーを外します。
- 再確保が完了するまで古いバッファを保持し、途中で失敗した確保も解放します。
- h-raylib 5.6のシェーダーモードは、終了時の描画バッチ処理まで`shader.locs`を保持する
  wrapperを使います。メッシュのnative借用とGPU資源には別々の解放責務があります。
- GPUへ渡した頂点のboxedリストをメタデータに残しません。今回追加したUV属性も対象です。
- WebGL 2の深度画像には、`GL_UNSIGNED_INT`に対応する`GL_DEPTH_COMPONENT24`を使います。
  WebGL 1用の非サイズ形式を流用すると、深度画像を使うバッファが不完全になりました。

## 再現できる確認

`cabal run noema-garden-check` はGPU不要です。既存の保存互換性・地形差分・衝突・
時計・巡回に加え、画質計画の寸法境界、無効な効果の省略、負座標の分割、広角の画面端、
検証モードのポインター非捕捉を調べます。生成ケースは合計800件です。

`cabal run noema-render-check -fnative` は実際の庭と同じ描画関数を使います。
昼・夜・夕方、三画質、効果の個別停止、1367×769の広角と傾き、701×1001の望遠、
再有効化を撮影し、さらに18回の品質変更で確保・解放を通します。
初回の形状生成後の一時データをGCで解放してから計測します。
CSVの時間はCPU側の描画とpresentを含み、GPUタイマーの計測ではありません。

通常のホストでも`GARDEN_FRAMES`、`GARDEN_SHOT`、`GARDEN_TOUR`による検証は既定で
`ObserveOnly`です。非表示ウィンドウを作り、キー・マウスを読まず、ポインターの操作も
行いません。明示的な`GARDEN_INPUT=interactive`で通常入力へ戻せます。
ブラウザはクリック前のプレビューで同じ描画を確認できます。

## この変更での測定（2026-09-27）

Windows / GHC 9.6.7 / NVIDIA GeForce RTX 3050 6GB Laptop GPU、1600×900、
初期世界280,361セル、同じ停止したゲームカメラ、UI非表示で各300フレームを3回実行しました。
最初の30フレームを除き、各回の分位を求め、その3回の中央値を下表へ記載しています。
120FPSのホスト上限を維持した比較です。専用GPUプロファイラーによる測定ではありません。

旧版は`e999366`の描画に、検証中のマウス非捕捉だけを加えた実行ファイルです。
新版の描画チャンク数は1,498、旧版は4,461。セル数・地形・モデルの詳細は同一です。

| 実装・設定 | 描画区間の中央値 | presentを含むフレームの中央値 | フレームp95 |
| --- | --- | --- | --- |
| 旧版・高画質 | 9.02 ms | 9.25 ms | 10.89 ms |
| 新版・高画質 | 6.80 ms | 8.33 ms | 9.03 ms |
| 新版・標準 | 6.73 ms | 8.33 ms | 8.92 ms |
| 新版・軽量 | 3.03 ms | 8.33 ms | 8.91 ms |

上限があるため、軽量化の余裕は主に描画区間の時間へ現れます。
このカメラで高画質と標準の差が小さいことも、別の場面や端末で差が小さいという意味ではありません。
動くプレイヤー、戦闘、編集を含むゲーム全体のGPU時間へ、この値を一般化しないでください。

初期読み込みは旧版の中央値3.43秒に対し、新版高画質5.31秒でした。
属性を増やしたメッシュの生成・転送に費用があり、フレーム中の改善と起動の増加を区別しています。
GPUへ転送したあとのboxed頂点保持を取り除いた後、ブラウザ起動中のメモリエラーも再現しなくなりました。

別途、ネイティブの描画チェックで12シーンと18回の切り替えを実行しました。
通常のゲーム入力を使う物語の自動巡回は、非捕捉モードで3,057 tick、地形revision 6、
全ての仲間を保護して帰還まで完走しました。壊れたシェーダーを渡す障害注入では、
エラーダイアログを開かず終了コード1とログで失敗を報告することも確認しました。
四島への飛行・着地・建築まで続けるネイティブ巡回も、9,068 tick、revision 10で完走しました。
ブラウザ実機ではWebGL 2のHDR、三つの画質、個別効果の切り替え、起動前プレビューを確認しています。
この機材以外のGPUや、HDRを持たない機材での見た目・性能は未確認です。
