# 時間・入力・保存

## tickへ入力を渡す

描画フレームで取得した入力を、そのまま状態更新一回と対応させない。
固定刻みなら、経過時間の残りと未消費の入力をschedulerに保持する。

| 入力の意味 | 複数tickを実行するとき | tickがないとき |
| --- | --- | --- |
| 押した瞬間 | 対象tickへ一度だけ渡す | 次のtickまで保持 |
| 押し続け | 各tickへ渡す | 最新の状態を保持 |
| マウス移動量 | 対象区間へ配分する | 累積する |

「二度押す」が意味を持つ入力はイベント列として保持する。BoolのORは回数と順序を失う。
入力APIが押下イベントをキューに積む場合は、frame冒頭で一度読み切り、
複数のconsumerへ同じ観測値を渡す。consumerごとにqueueを消費しない。
フォーカス復帰・メニュー・ポーズでは保留入力と経過時間をどう扱うかを決める。

同じtickの視点変更を先に反映してから、カメラ相対移動や照準を解決する。
遅れを分割処理するときも、確定済み入力を新しいデバイス状態で置き換えない。
余剰時間の破棄は暗黙の最適化にせず、許す場合はその時間モデルとして明記する。

**確認**: tickなしのフレーム、長い停止後の復帰、同時の視点変更と移動、
押下の重複・消失、累積移動量、継続実行と分割実行の一致。

## 時計とFRP

離散的な期限にはtick・期間・締切の意味を持つ型を使い、境界の包含関係を定める。
減算の負値、上限、ゼロ期間も契約に含む。局所時計や異なる更新周期は、
明示した速度・位相から導く。実時計や描画回数を隠れた時計にしない。

FRPはイベントの合成、遅延、切替、同時性などに使う。SFは初期化後の継続を保持し、
選んだ意味時計で進める。描画フレームごとに初期化し直さない。通常の移動式や衝突式を
包むだけなら純粋関数でよい。FRPのmerge順に同時イベントの勝者を決めさせない。
利用箇所は本番経路を通る観測可能な結果で確認する。

時間的な動作を再構築するには、継続オブジェクトではなく十分な種を保存する。
例えば主体ID、状態、開始tick、期限、速度、依存先。
`許可された状態 && 開始 <= 現在 && 現在 < 期限`のように活動条件を書く。
状態から離れた主体の古いタイマーは発火させない。

## 保存する意味を選ぶ

将来の結果に影響する値と、再開時に保持する体験をSnapshotとして定義する。
デバイスハンドル、GPU資源、関数、FRPの内部継続、性能ログは保存対象にしない。
物理のwarm startなど、後続結果を変える内部値は保存または同等の再構築が必要。
純粋なWorldの全フィールドが永続化すべきものとは限らない。

差分保存には基準世界の識別を含める。地形生成を変えた後に同じ差分を無条件に
適用すると別の世界を復元してしまう。形式の版、移行、サイズ・値域・参照の検証を分ける。
境界で受理できた状態と、その後の遷移でも不変条件を保つ状態を混同しない。

再開検査は後の最終状態だけでなく、**直後**の表示・有効効果・衝突も比較する。
過去の音を再生しない、将来のイベントを先に出さない、キャンセル済み期限を復活させない。
消す予定の一時効果はその再開契約に従って比較する。

実行中に合法な状態でも、codecの件数・値域制限に収まるとは限らない。
保存可能な範囲を状態遷移で保つか、書く前に復元側と同じ受理条件を検査し、
拒否を保存失敗として返す。書込み成功を次回ロード成功と取り違えない。

IOでは一時ファイルと置換で旧saveを保つ。「保存して終了」は保存成功後に進め、
失敗時は生きた状態と旧saveを保持する。遅延読み込みのまま元ファイルを
コピー・移動・置換しない。読み込みと評価を例外処理の範囲内で完了させるか厳密IOを使う。
壊れた内容の保全失敗と解析失敗も区別する。
