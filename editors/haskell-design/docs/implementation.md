# Haskell Design delivery

Provide the same declaration projection, IO evidence and Git design diff in VS Code and Neovim. Keep source as the only editable truth. A shared Haskell library and pinned native Tree-sitter Haskell grammar handle unsaved source without executing a project. The standalone Haskell CLI uses that library directly; editor adapters call its JSON-line server. A GHC helper checks saved source, infers types, finds IO in resolved types and typed source expressions. Never infer Pure from missing text or an unavailable compiler. GHC verification runs automatically inside the editor's trusted project scope; ordinary design browsing needs no trust. See automatic-design.md for the editor contract and native.md for the current code boundaries.

VS Code uses a default CustomTextEditorProvider for .hs, backed by the native TextDocument. Source/design transitions stay in the current editor group. Clean alternate tabs close; dirty alternates stay open because VS Code may revert their shared document when closing them. No implicit save or reconstruction of edits is used. Neovim displays a read-only design buffer in the same window, keeping the source buffer and undo history. An explicit source transition suppresses automatic reopening; deferred parsing never changes window focus. Native diff windows remain native. Both show implementations on demand and refresh when source changes.

A shared pure file-tree model aggregates IO/Pure/unavailable counts through every ancestor. Pure requires nonempty, complete descendants whose GHC type information contains no IO. A truncated scan retains an unavailable state. Unsaved buffers override disk content in the tree. VS Code exposes the hierarchy and native folder decorations; Neovim decorates the ordinary mini.files browser; the optional collapsible tree remains available. Native VS Code badges use P because of their character limit, while full views spell Pure.

The public Afterlight repository distributes source and setup skills. Local builds produce OS/CPU-specific VSIX and Neovim packages with the native executable, dependency notices and runnable examples. Build products and test runtime state are ignored by Git.

Compiler compatibility is GHC 9.6.x. Unsupported compiler versions retain syntax features and report unknown verification. Package/include configuration is explicit rather than guessed; `.haskell-design.json` shares common and component-specific settings between editors. Compiler configuration and Cabal inputs participate in proof invalidation. Unsupported components carry a concrete explanation.

Classification is a bounded search for concrete IO in GHC types, not a Safe Haskell audit. Aliases and concrete type-family reductions are expanded; abstract effects add no IO evidence. Source-module fields are inspected, while external library representations stay abstract. Public IO types and typed source occurrences still count. GHC-produced copies of imported defaults are excluded by AST origin, while user-written instance methods remain included. Successful GHC results override provisional syntax hints. See automatic-design.md for the full contract. Template Haskell, quasiquotes, annotations, CPP and compiler plugins do not yield reusable analysis. No application entrypoint is run.

Neovim's `source_path()` resolves a design or folder projection to a real path for integrations such as mini.files; a scratch buffer title must never be handed to a filesystem API.
